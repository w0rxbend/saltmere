# Saltmere

A personal daily learning journal, published automatically twice a day (09:00 & 21:00 Europe/Kyiv) by a scheduled Claude task.

Each run researches the web and a curated reading list, then writes 1–3 short, **implementable** articles across a rotating set of topic tracks:

- **Distributed Systems** — following *Distributed Systems* (4th ed.) by van Steen & Tanenbaum
- **Practical Linux Tools** — CLI tools and small systems experiments
- **Scala 3 & the JVM**
- **IoT & Embedded** — Arduino, ESP32, air-quality sensors, large IoT backends
- **Monitoring & Observability**
- **CAD & 3D Printing** — FreeCAD (parametric), KiCad, print pipeline

## How it's built

- Static site generated by **Jekyll** (GitHub Pages zero-build). No bundler, no
  npm, no build step — the browser loads the CSS and JS files directly.
- Articles live in `_articles/<track>/` as Markdown with front matter (`title`, `date`, `track`, `summary`, `tags`, `sources`, `reading_time`).
- The home page (`index.md`) shows the latest drop and every track; each track
  also gets its own page at `/tracks/<id>/` (the stubs in `tracks/`).
- Layouts in `_layouts/` (`default`, `article`, `track`), styles in
  `assets/style.css`, behaviour in `assets/app.js`.

### The interface

- **Theme** — dark by default, with a light theme. The toggle in the header
  remembers your choice in `localStorage`; if you have never touched it, the
  site follows your operating system's setting. A small script in `<head>`
  applies the saved theme before the first paint, so there is no flash of the
  wrong colours on load.
- **Search** — press <kbd>Cmd-K</kbd> / <kbd>Ctrl-K</kbd> (or just <kbd>/</kbd>)
  anywhere to open a search box covering every article. It is entirely
  client-side: `search.json` is a Jekyll-generated index of every title,
  summary, tag and track, fetched once when you first open the box and then
  filtered in the browser. There is no search server and no third-party service.
- **Navigation** — a Tracks dropdown in the header, filter chips on the home
  page that show one track at a time, and previous/next links at the foot of
  every article that walk you through its own track.
- **Colour per track** — each of the eight tracks has its own accent colour,
  set once as a CSS custom property (`--track`) and reused by cards, headings,
  list rows and code-block borders.

Everything degrades gracefully: with JavaScript turned off you still get every
article, every link and the full track listings — you only lose search,
filtering and the theme toggle.

## Local preview

The real site is built by Jekyll, which needs Ruby:

```bash
bundle install
bundle exec jekyll serve
```

If you do not have Ruby to hand, `tools/preview.py` renders the same pages with
a small Python stand-in that implements only the Liquid features these layouts
actually use. It is a development aid for checking the design, not a
replacement for Jekyll:

```bash
pip install python-liquid pyyaml markdown
python3 tools/preview.py
python3 -m http.server -d _preview 8080
```

## Adding an article

Create `_articles/<track>/YYYY-MM-DD-slug.md`:

```yaml
---
title: Your title
date: 2026-07-24
track: linux-tools        # one of the track ids in _config.yml
summary: One-sentence hook.
reading_time: 4
tags: [example, cli]
sources:
  - title: Source name
    url: https://example.com
---

Article body in Markdown…
```

### Escaping other tools' templates

Jekyll runs each article through Liquid first, and Liquid owns `{% raw %}{% ... %}{% endraw %}`
and `{% raw %}{{ ... }}{% endraw %}`. Many tools these articles cover use the same braces —
GitHub Actions, Prometheus, Vault, Argo, Helm, Jinja, Klipper. An unescaped
snippet either aborts the build or silently renders as nothing, so wrap the
code block:

    {% raw %}
    ```yaml
    token: ${{ secrets.WOKWI_CLI_TOKEN }}
    ```
    {% endraw %}

`python3 tools/check_liquid.py` flags any article that needs this; CI runs it
before the Jekyll build so a mistake names the file and line rather than
producing a Ruby stack trace. Deliberate Liquid in prose, such as a
`{% raw %}{{ site.baseurl }}{% endraw %}` cross-link, is fine and left alone.
