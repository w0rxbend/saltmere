**Gist.** Volatile organic compound (VOC) sensors such as the CCS811 and SGP30 do not measure carbon dioxide; they report an **equivalent CO2 (eCO2)** figure derived from a VOC model, so solvents, cooking fumes and fresh paint move the number without any change in CO2. The Sensirion SCD41 measures CO2 directly with a photoacoustic non-dispersive infrared (NDIR) cell, which ties the signal to the specific infrared absorption band of CO2. The cost is a heavier host protocol: a fixed 5-second sampling cadence, a mode distinction between periodic measurement and idle, a per-word checksum on every transfer, and an automatic baseline correction whose assumptions must hold or the readings drift.

## Measurement principle

An infrared emitter pulses at the CO2 absorption band. Gas molecules in a small cavity absorb that energy and expand, and a microelectromechanical systems (MEMS) microphone detects the resulting pressure pulse. Higher CO2 concentration yields a larger acoustic signal. Because the excitation is confined to the CO2 absorption band, compounds that dominate a VOC sensor's response do not produce a proportional photoacoustic signal.

Datasheet accuracy is specified as **a fixed offset in ppm plus a percentage of the reading**, so the absolute error grows with concentration; the tightest band is the one around ambient outdoor air, and the specification loosens over the wider measurement range. The exact figures belong to the datasheet revision in use rather than to any general rule about the part.

## The I2C interface

The device answers at **7-bit address 0x62** and tolerates a bus clock up to **400 kHz**. Every command is a 16-bit code transmitted big-endian, most significant byte first. A minimal logger uses four:

| Command | Code | Notes |
|---|---|---|
| `start_periodic_measurement` | `0x21B1` | Begins auto-sampling every 5 s |
| `get_data_ready_status` | `0xE4B8` | Returns a word; low 11 bits nonzero = ready |
| `read_measurement` | `0xEC05` | Returns 9 bytes: CO2, T, RH |
| `stop_periodic_measurement` | `0x3F86` | Required before most config commands; ~500 ms |

The device has **two modes**, and the distinction is load-bearing. After `start_periodic_measurement` it produces a fresh sample **every 5 seconds**; polling faster returns the previously latched value rather than new data. Configuration commands — sensor altitude, automatic self-calibration — are **accepted only in idle mode**, so the sequence for any reconfiguration is stop, wait for the stop command's ~500 ms completion, configure, restart.

The data-ready word exists because the host has no interrupt line to wait on. Its **low 11 bits** carry the readiness flag: a value of zero in those bits means no unread sample is pending. Testing the whole 16-bit word instead of masking to the low 11 bits is a common defect, because the upper bits are not guaranteed zero.

## CRC-8 on every word

`read_measurement` returns **three 16-bit words, each followed by its own CRC-8 byte — nine bytes in total, not six**. The checksum is computed over the two data bytes of that word with **polynomial 0x31 (x^8 + x^5 + x^4 + 1) and initial value 0xFF**. The same construction applies to the three-byte reply of `get_data_ready_status`.

Omitting the check does not fail loudly. A single corrupted bit on a marginal bus — long jumper leads, missing or oversized pull-up resistors, an unshielded run next to a switching supply — is accepted as a legitimate word, and a corrupted high byte of the CO2 word can place the reading anywhere in the **0–40000 ppm** range. The observable symptom is an isolated vertical spike in a time series that is otherwise smooth, with no corresponding physical event. Validating all three CRCs and discarding the whole nine-byte frame on any mismatch converts that silent corruption into a dropped sample.

The datasheet conversions:

- **CO2 [ppm] = word0** (already in ppm, range 0–40000)
- **T [degC] = -45 + 175 * word1 / 65535**
- **RH [%] = 100 * word2 / 65535**

## Minimal ESP32 sketch (raw I2C)

No vendor library, only `Wire`, so that the exact bus traffic remains visible.

```cpp
#include <Wire.h>
#define SCD41_ADDR 0x62

uint8_t crc8(const uint8_t *data, uint8_t len) {
  uint8_t crc = 0xFF;
  for (uint8_t i = 0; i < len; i++) {
    crc ^= data[i];
    for (uint8_t b = 0; b < 8; b++)
      crc = (crc & 0x80) ? (crc << 1) ^ 0x31 : (crc << 1);
  }
  return crc;
}

void sendCmd(uint16_t cmd) {
  Wire.beginTransmission(SCD41_ADDR);
  Wire.write(cmd >> 8);
  Wire.write(cmd & 0xFF);
  Wire.endTransmission();
}

bool dataReady() {
  sendCmd(0xE4B8);                 // get_data_ready_status
  delay(1);
  Wire.requestFrom(SCD41_ADDR, 3);
  uint8_t b[3];
  for (int i = 0; i < 3; i++) b[i] = Wire.read();
  if (crc8(b, 2) != b[2]) return false;
  return ((b[0] << 8 | b[1]) & 0x07FF) != 0;   // low 11 bits carry the flag
}

void setup() {
  Serial.begin(115200);
  Wire.begin();                    // ESP32 default SDA=21, SCL=22
  sendCmd(0x21B1);                 // start_periodic_measurement
  delay(5000);                     // first sample after ~5 s
}

void loop() {
  if (dataReady()) {
    sendCmd(0xEC05);               // read_measurement
    delay(1);
    Wire.requestFrom(SCD41_ADDR, 9);
    uint8_t d[9];
    for (int i = 0; i < 9; i++) d[i] = Wire.read();
    // one bad CRC invalidates the whole frame, not only its own word
    if (crc8(d,2)==d[2] && crc8(d+3,2)==d[5] && crc8(d+6,2)==d[8]) {
      uint16_t co2 = d[0] << 8 | d[1];
      float t  = -45.0f + 175.0f * (d[3] << 8 | d[4]) / 65535.0f;
      float rh = 100.0f * (d[6] << 8 | d[7]) / 65535.0f;
      Serial.printf("CO2 %u ppm  T %.1f C  RH %.0f %%\n", co2, t, rh);
    }
  }
  delay(5000);
}
```

## Pressure and altitude compensation

NDIR response depends on gas density, so ambient pressure enters the result. Two commands correct for it, and they differ in when they may be issued:

- **`set_ambient_pressure` (0xE000)** takes pressure in **hectopascals (hPa)** and may be sent **during periodic measurement**, which suits a design carrying a separate barometric sensor and feeding live values in.
- **`set_sensor_altitude` (0x2427)** takes metres above sea level and is **idle-mode only**, so it is set once during initialisation and the device assumes standard pressure for that altitude thereafter.

The two are alternative expressions of the same correction; applying both leaves the device operating on whichever was written last rather than on a combined figure.

## Automatic self-calibration

**Automatic self-calibration (ASC) is enabled by default.** It assumes the device periodically sees fresh outdoor air near 400 ppm and re-anchors its baseline to the minimum concentration observed. Sensirion states the requirement as regular exposure to fresh-air concentrations together with enough continuous powered operation for the algorithm to accumulate a baseline; the specific exposure interval and run-time minimum are given in the datasheet and should be read from the revision in hand.

The failure modes follow directly from that assumption. A device sealed in a room that never reaches fresh-air concentrations still anchors its baseline to the lowest value it observes, which is above 400 ppm; the baseline is pulled **too high** and subsequent readings drift low over a period of weeks. Sustained exposure to concentrations **below** 400 ppm breaks the assumption in the other direction and degrades accuracy while ASC is enabled.

A device running continuously in a normally ventilated home satisfies the assumption, and ASC can remain enabled. A device in a grow tent, a sealed enclosure, or one powered on only intermittently does not, and **ASC is disabled with `set_automatic_self_calibration_enabled` (0x2416)** in idle mode, with a forced recalibration against a known reference performed instead.

## Pitfalls

- **Reading six bytes from `read_measurement`.** The reply is nine bytes; a six-byte read leaves three bytes queued and the next transfer returns misaligned data that decodes as plausible but wrong values.
- **Skipping the CRC.** A single flipped bit in the CO2 word is accepted as a real reading anywhere within 0–40000 ppm, appearing as an isolated spike with no physical cause.
- **Testing the full data-ready word for nonzero.** Only the low 11 bits carry the flag; the upper bits are not guaranteed zero, so an unmasked test can report data ready when none is pending.
- **Issuing configuration commands during periodic measurement.** Altitude and ASC commands are accepted only in idle mode, so the write is rejected and the device silently keeps its previous configuration.
- **Restarting measurement immediately after `stop_periodic_measurement`.** That command takes about 500 ms to complete; commands sent inside that window are not processed.
- **Polling faster than the 5-second cadence.** The device latches one sample per interval, so a faster loop re-reads the same value and produces a time series with artificial flat steps.
- **Setting both altitude and ambient pressure.** They are alternative forms of the same compensation, and the device applies whichever was written most recently rather than combining them.
- **Leaving ASC enabled in a sealed enclosure.** The baseline anchors to the lowest concentration seen, which exceeds 400 ppm, and readings bias progressively low over weeks with no error indication.
