**Gist.** The Plantower PMS5003 reports particulate matter (PM) mass concentrations over a plain asynchronous serial link with no register map and no per-word cyclic redundancy check, so the host must recover structure from a byte stream that carries only a two-byte start marker and a 16-bit additive checksum. The mechanism is a **fixed 32-byte frame** transmitted at **9600 baud, 8N1** on a 3.3 V TTL universal asynchronous receiver/transmitter (UART), which the host resynchronizes on and verifies before decoding. The cost is that every guarantee — alignment, integrity, which of two calibrations a number belongs to — is the host's responsibility, and a single misinterpreted offset produces readings that are plausible and wrong.

The sensor is a laser-scattering particle counter: a fan pulls air past a laser, a photodiode measures scattered light, and an onboard microcontroller converts pulse events into PM1.0/PM2.5/PM10 mass concentrations. Unlike the Sensirion SEN5x or SEN66, which speak Inter-Integrated Circuit (I2C) with per-word checksums, the PMS5003 streams frames unsolicited in its default mode: after power-up, frames arrive with no request from the host, at an interval the manual gives as about 2.3 s in the stable state and 200–800 ms while the readings are changing.

## The 32-byte frame

Every frame begins with the two ASCII bytes **`0x42 0x4D`** ("BM"), followed by a 16-bit **frame length** field of `0x00 0x1E` (30 — the count of bytes that follow, up to and including the checksum). Thirteen big-endian 16-bit data words and a 16-bit checksum complete the frame.

| Offset | Word | Meaning |
|--------|------|---------|
| 0–1 | — | Start chars `0x42 0x4D` |
| 2–3 | — | Frame length `0x00 0x1E` (30) |
| 4–5 | Data1 | PM1.0 µg/m³ — **CF=1, standard particle** |
| 6–7 | Data2 | PM2.5 µg/m³ — **CF=1, standard particle** |
| 8–9 | Data3 | PM10 µg/m³ — **CF=1, standard particle** |
| 10–11 | Data4 | PM1.0 µg/m³ — **atmospheric environment** |
| 12–13 | Data5 | PM2.5 µg/m³ — **atmospheric environment** |
| 14–15 | Data6 | PM10 µg/m³ — **atmospheric environment** |
| 16–27 | Data7–12 | Particle counts per 0.1 L for ≥0.3/0.5/1.0/2.5/5.0/10 µm |
| 28–29 | Data13 | Reserved |
| 30–31 | — | Checksum |

Two invariants make the frame self-describing enough to validate: **the length field is constant at 30 for this device**, so any other value indicates a misaligned window rather than a variable-length payload, and **the frame is a fixed 32 bytes**, so the parser never needs to consume a length before knowing how much to read.

**CF=1 "standard particle" versus "atmospheric environment"** is the field pair most often confused. The manual labels Data1–3 as CF=1, standard particle and Data4–6 as atmospheric environment; it does not document the transformation between the two sets, so the difference is observable only in the emitted numbers. At low concentrations the two sets are frequently identical and they separate as concentration rises, which is why a mixed-convention dashboard looks correct during the periods when it matters least. A single convention, labelled at the point of ingestion, is the only way the difference stays falsifiable.

All six mass fields are already expressed in µg/m³, so **no scaling is applied after decoding**.

## The checksum

The checksum is the least significant 16 bits of the **arithmetic sum of the first 30 bytes** — the two start characters through Data13, excluding the checksum bytes themselves. There is no polynomial and no bit reflection, so the check is an unsigned accumulate-and-compare. Its weakness follows from that structure: an additive sum over bytes is insensitive to byte order, so **a permutation of the payload bytes still verifies**, and two compensating errors of equal and opposite magnitude cancel. It detects the common failure — a corrupted or truncated byte on a marginal jumper wire — and detects nothing about alignment beyond what the constant length field already implies.

## Resynchronization

Framing on an unsolicited stream has one state variable: whether the reader currently sits on a frame boundary. A UART with no flow control loses that position whenever a byte is dropped — a receive overrun, a missed interrupt, a host that starts reading mid-frame at boot. Because the payload can contain the byte `0x42` at any offset, **recovering alignment requires scanning byte-by-byte for the `0x42 0x4D` pair and then confirming with the length field and the checksum**; a header match alone is not proof of a frame boundary. A parser that reads 32 bytes at a fixed stride and trusts them will, after a single dropped byte, decode every subsequent frame at a constant wrong offset and continue indefinitely.

## A validating ESP-IDF parser

The pattern below reads into a scan buffer, resynchronizes on the header, and validates length and checksum before decoding. Rejection is silent and the caller retries on the next frame; discarding a frame costs one sample.

```c
#include "driver/uart.h"
#include "esp_log.h"

#define PMS_UART   UART_NUM_2
#define PMS_TX     17            // ESP32 TX -> PMS RX (for commands)
#define PMS_RX     16            // ESP32 RX <- PMS TX (frame stream)

typedef struct { uint16_t pm1_0, pm2_5, pm10; } pm_atm_t;   // atmospheric

void pms_init(void) {
    uart_config_t cfg = {
        .baud_rate = 9600, .data_bits = UART_DATA_8_BITS,
        .parity = UART_PARITY_DISABLE, .stop_bits = UART_STOP_BITS_1,
        .flow_ctrl = UART_HW_FLOWCTRL_DISABLE,
        .source_clk = UART_SCLK_DEFAULT,
    };
    uart_param_config(PMS_UART, &cfg);
    uart_set_pin(PMS_UART, PMS_TX, PMS_RX,
                 UART_PIN_NO_CHANGE, UART_PIN_NO_CHANGE);
    uart_driver_install(PMS_UART, 256, 0, 0, NULL, 0);
}

// Returns true and fills *out when a valid frame is decoded.
bool pms_read(pm_atm_t *out) {
    uint8_t f[32];
    // Consume one byte per call until it is 0x42, so a misaligned
    // stream advances by a single byte instead of a whole frame.
    uint8_t b;
    if (uart_read_bytes(PMS_UART, &b, 1, pdMS_TO_TICKS(3000)) != 1) return false;  // > 2.3 s stable interval
    if (b != 0x42) return false;
    if (uart_read_bytes(PMS_UART, &b, 1, pdMS_TO_TICKS(50)) != 1 || b != 0x4D)
        return false;
    f[0] = 0x42; f[1] = 0x4D;
    if (uart_read_bytes(PMS_UART, f + 2, 30, pdMS_TO_TICKS(100)) != 30)
        return false;

    uint16_t frame_len = (f[2] << 8) | f[3];      // must be 0x001E (30)
    if (frame_len != 30) return false;

    uint16_t sum = 0;
    for (int i = 0; i < 30; i++) sum += f[i];      // sum of first 30 bytes
    uint16_t chk = (f[30] << 8) | f[31];
    if (sum != chk) return false;                  // reject corrupt frame

    out->pm1_0 = (f[10] << 8) | f[11];             // Data4: PM1.0 atmospheric
    out->pm2_5 = (f[12] << 8) | f[13];             // Data5: PM2.5 atmospheric
    out->pm10  = (f[14] << 8) | f[15];             // Data6: PM10 atmospheric
    return true;
}
```

The 256-byte driver ring buffer holds eight 32-byte frames, so at the fastest documented active-mode interval of 200 ms it fills in about 1.6 s: the service interval, not the sample interval, sets the overrun margin. `sum` is declared `uint16_t`, which makes the required truncation to sixteen bits implicit in the accumulator's own arithmetic. The lab-calibrated CF=1 values occupy `f[4..9]` (Data1–3) and decode identically.

## Active mode, passive mode, and the two pins

The default state is **active mode**: the sensor pushes frames unprompted, at about 2.3 s intervals in the stable state and 200–800 ms when the concentration is changing, and the host transmits nothing. Passive mode is entered by writing `42 4D E1 00 00 01 70`, after which each frame is requested with `42 4D E2 00 00 01 71`. Every command has the same shape: start characters, one command byte, two data bytes, and a two-byte checksum. Wake and sleep are `42 4D E4 00 01 …` and `42 4D E4 00 00 …` respectively.

Two hardware pins duplicate part of that control surface. **SET (pin 3)** is the sleep line: high or floating leaves the sensor running, pulled low puts it to sleep, with the same effect as the sleep command. **RESET (pin 6)** is an active-low reset.

The timing constraint applies in every mode. Plantower's manual states that stable data should be taken at least 30 seconds after the sensor wakes from sleep, so **frames from the first 30 seconds after wake must be discarded**. They are structurally valid and pass the checksum; only their timestamp distinguishes the warm-up ramp from settled air.

## Pitfalls

- **Mixing CF=1 and atmospheric fields across a dataset.** Readings agree at low concentration and separate as concentration rises, so a mislabelled series looks self-consistent until the episode it was deployed to capture.
- **Reading at a fixed 32-byte stride without header search.** One dropped byte shifts every later frame by a constant offset; the checksum then rejects continuously, or — if the shifted window happens to sum correctly — decodes particle counts as mass concentrations.
- **Treating a `0x42 0x4D` match as a frame boundary.** Those byte values occur inside the payload, so alignment is confirmed only after the length field and checksum agree.
- **Trusting the additive checksum as an integrity guarantee.** It is a byte sum, not a cyclic redundancy check: reordered bytes and pairs of compensating errors pass it unchanged.
- **Logging frames from the first 30 seconds after wake.** They are well-formed and pass validation, but they fall inside the interval the manual excludes from stable data — which biases a duty-cycled battery node's entire record.
- **Accumulating the checksum in a wider type without masking.** A `uint32_t` accumulator compared directly against the 16-bit field mismatches whenever the true sum exceeds 65535.
- **Servicing the UART too slowly.** A 256-byte driver buffer holds eight 32-byte frames, which at the fastest documented 200 ms interval is about 1.6 s of stream; a slower service loop overruns the ring and drops bytes mid-frame, which is exactly the condition that costs alignment.
