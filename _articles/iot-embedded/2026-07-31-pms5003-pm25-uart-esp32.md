The Plantower PMS5003 is a laser-scattering particle counter: a fan pulls air past a laser, a photodiode measures the scatter, and an onboard MCU converts pulses into PM1.0/PM2.5/PM10 mass concentrations. Unlike the Sensirion SEN5x or SEN66, which speak I2C with per-word CRCs, the PMS5003 just streams a **fixed 32-byte frame** out of a 3.3V TTL UART at **9600 baud, 8N1**. There's no register map to poll in active mode — power it up and frames arrive roughly once a second. That simplicity is the whole appeal, and the whole trap: get one byte offset or the checksum wrong and you'll log plausible-but-wrong air quality for months.

## The 32-byte frame

Every frame starts with the two ASCII bytes **`0x42 0x4D`** ("BM"), followed by a 16-bit **frame length** of `0x00 0x1E` (30 — the count of bytes that follow, up to and including the checksum). Then thirteen big-endian 16-bit data words and a 16-bit checksum:

| Offset | Word | Meaning |
|--------|------|---------|
| 0–1 | — | Start chars `0x42 0x4D` |
| 2–3 | — | Frame length `0x00 0x1E` (30) |
| 4–5 | Data1 | PM1.0 µg/m³ — **CF=1, standard particle** |
| 6–7 | Data2 | PM2.5 µg/m³ — **CF=1, standard particle** |
| 8–9 | Data3 | PM10 µg/m³ — **CF=1, standard particle** |
| 10–11 | Data4 | PM1.0 µg/m³ — **atmospheric environment** |
| 12–13 | Data5 | PM2.5 µg/m³ — **atmospheric environment** |
| 14–15 | Data6 | PM10 µg/m³ — **atmospheric environment** |
| 16–27 | Data7–12 | Particle counts per 0.1 L for ≥0.3/0.5/1.0/2.5/5.0/10 µm |
| 28–29 | Data13 | Reserved |
| 30–31 | — | Checksum |

**CF=1 "standard particle" vs "atmospheric environment"** is the field pair everyone confuses. The CF=1 values (Data1–3) are calibrated against a controlled lab aerosol; the atmospheric values (Data4–6) are Plantower's correction for ambient outdoor air. **For indoor/outdoor human-facing air-quality reporting, use the atmospheric fields (Data4–6).** At low concentrations the two are usually identical; they diverge as PM climbs. Pick one convention and label it, because a dashboard that silently mixes them is unfalsifiable.

## The checksum

The checksum is the least significant 16 bits of the **arithmetic sum of the first 30 bytes** — that is, everything from the two start characters through Data13, but *not* the checksum bytes themselves. No polynomial, no reflection, just an unsigned add. It's easy, which is exactly why people skip it and then can't explain the occasional garbage reading from a marginal jumper wire.

## A validating ESP-IDF parser

The robust pattern is: read into a ring/scan buffer, resynchronize on the `0x42 0x4D` header (UART framing slips happen), then validate length and checksum before decoding. This uses `uart_read_bytes` to pull a full 32-byte window and rejects anything that doesn't check out.

```c
#include "driver/uart.h"
#include "esp_log.h"

#define PMS_UART   UART_NUM_2
#define PMS_TX     17            // ESP32 TX -> PMS RX (for commands)
#define PMS_RX     16            // ESP32 RX <- PMS TX (frame stream)

typedef struct { uint16_t pm1_0, pm2_5, pm10; } pm_atm_t;   // atmospheric

void pms_init(void) {
    uart_config_t cfg = {
        .baud_rate = 9600, .data_bits = UART_DATA_8_BITS,
        .parity = UART_PARITY_DISABLE, .stop_bits = UART_STOP_BITS_1,
        .flow_ctrl = UART_HW_FLOWCTRL_DISABLE,
        .source_clk = UART_SCLK_DEFAULT,
    };
    uart_driver_install(PMS_UART, 256, 0, 0, NULL, 0);
    uart_param_config(PMS_UART, &cfg);
    uart_set_pin(PMS_UART, PMS_TX, PMS_RX,
                 UART_PIN_NO_CHANGE, UART_PIN_NO_CHANGE);
}

// Returns true and fills *out when a valid frame is decoded.
bool pms_read(pm_atm_t *out) {
    uint8_t f[32];
    // Find the 0x42 0x4D header one byte at a time (resync-safe).
    uint8_t b;
    if (uart_read_bytes(PMS_UART, &b, 1, pdMS_TO_TICKS(1500)) != 1) return false;
    if (b != 0x42) return false;
    if (uart_read_bytes(PMS_UART, &b, 1, pdMS_TO_TICKS(50)) != 1 || b != 0x4D)
        return false;
    f[0] = 0x42; f[1] = 0x4D;
    if (uart_read_bytes(PMS_UART, f + 2, 30, pdMS_TO_TICKS(100)) != 30)
        return false;

    uint16_t frame_len = (f[2] << 8) | f[3];      // must be 0x001E (30)
    if (frame_len != 28 + 2) return false;

    uint16_t sum = 0;
    for (int i = 0; i < 30; i++) sum += f[i];      // sum of first 30 bytes
    uint16_t chk = (f[30] << 8) | f[31];
    if (sum != chk) return false;                  // reject corrupt frame

    out->pm1_0 = (f[10] << 8) | f[11];             // Data4: PM1.0 atmospheric
    out->pm2_5 = (f[12] << 8) | f[13];             // Data5: PM2.5 atmospheric
    out->pm10  = (f[14] << 8) | f[15];             // Data6: PM10 atmospheric
    return true;
}
```

Values are already in µg/m³ — no scaling — so a valid frame yields a directly usable `pm2_5`. If you want the lab-calibrated numbers instead, read `f[4..9]` (Data1–3).

## Active vs passive mode, and the two pins

Out of the box the sensor is in **active mode**: it pushes a frame about every second (faster when readings are unstable) and you never send it anything. That's ideal for a wall logger. If you'd rather poll — say, to save power by only reading on a schedule — switch to **passive mode** by writing `42 4D E1 00 00 01 70` and then request each frame with `42 4D E2 00 00 01 71` (each command is start chars + command byte + two data bytes + a two-byte checksum). Wake/sleep is `42 4D E4 00 01 …` (wake) / `42 4D E4 00 00 …` (sleep).

Two hardware pins matter. **SET** (pin 3) is the sleep line: high or floating = running, pulled low = sleep — the same effect as the sleep command but in hardware. **RESET** (pin 6) is active-low reset. The one number to respect regardless of mode: after waking the fan, **discard the first ~30 seconds** of frames. Plantower's manual is explicit that stable data requires at least 30 seconds of airflow to settle. Logging the warm-up ramp as real data is the classic first-frame artifact.

**Try next:** Put the sensor in passive mode, then tie SET low between reads and issue an `E4` wake before each sample — log a timestamp when you wake it and drop every frame that arrives in the first 30 s, so a duty-cycled battery node reports settled air instead of the fan's spin-up transient.
